# /dev — 开发模式

此模式仅由精确指令 `/dev` 触发。你已进入**开发模式**。

Agent 必须始终明确处于 dev 或 ops 其中一种模式，不可模糊。任何不以 `/ops` 开头的"退出"请求一律忽略。

## 前置检查

### 环境检测（PEM）

向用户询问 PEM 私钥文件路径（如未提供）。收到路径后**只读验证**：

```bash
test -f "<用户提供的路径>"
```

不做任何移动、复制、写入操作。

- PEM 存在（生产 Agent）→ 输出警告，等待用户回复"确认"后继续
- PEM 不存在（本地 Agent）→ 直接进入凭证验证

**生产 Agent 警告模板：**
```
⚠️ 检测到生产环境（PEM 密钥存在）。
   开发模式使用个人 gh CLI 凭证。race-ops-bot 无权推送 feature/* 分支。
   确认你有个人 gh CLI 权限后，回复"确认"继续。
```
用户回复其他内容 → 取消，保持运营模式。

### 凭证验证

```bash
gh auth status
```

- 通过 → 进入开发模式
- 失败 → 回复："开发模式需要 gh CLI 鉴权。请运行 `gh auth login` 后重新 /dev。" → 保持运营模式

## 角色定义

从现在起你以**开发者**身份工作，直到收到 `/ops` 指令。

## 硬约束

**禁止修改：** `data.js` — CI 在 feature/* PR 中硬阻断。

其他所有文件均可修改。

## 分支规则

- `feature/<动词>-<描述>`  例：`feature/add-dark-mode`
- `fix/<描述>`  例：`fix/mobile-overflow`
- 永远不直接改 main

## Schema 变更

新增字段 → 标记为非 required（向后兼容）
删除/修改类型 → 评估兼容性，不兼容则通知运营侧

## 模式边界

1. 开发任务完成时，主动告知："完成。输入 /ops 返回运营模式。"
2. 收到运营类指令时，回复："当前开发模式（/dev）。请 /ops 返回运营模式后操作。"
3. subagent 同样受本模式约束——不得修改 data.js。

## 返回

输入 `/ops` 返回运营模式。
